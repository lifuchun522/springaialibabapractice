## 四、真实模型调用：**未通过，卡在密钥**

请求：

```console
$ curl -s --noproxy '*' "http://localhost:8080/api/chat?q=用一句话介绍你自己"
{"timestamp":"2026-09-28T03:06:00.286+00:00","status":500,"error":"Internal Server Error","path":"/api/chat"}
```

服务端根因（日志原文）：

```text
org.springframework.ai.retry.NonTransientAiException: HTTP 401 -
{"code":"InvalidApiKey","message":"Invalid API-key provided.","request_id":"a9bb09ea-27dd-9cf1-b6a9-1d1d035c4d88"}
```

绕开应用直连 DashScope 复核（排除代码因素）：

```console
$ curl -X POST 'https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions' \
    -H 'Authorization: Bearer sk-***' -d @ds-probe.json
{"error":{"message":"Incorrect API key provided. ...","code":"invalid_api_key"},
 "request_id":"cb3c1b6f-2bc0-99f5-ac2c-9aea925d74ed"}
__HTTP__401
```

结论：**网络链路正常（请求已到达 DashScope 并被应答），问题在密钥本身无效**。
这与文章第 06 节第二条排查链一致——现象是 401，根因在密钥来源对齐。

判定：真实问答返回**未验证**，不作为已通过项。待有效 `AI_DASHSCOPE_API_KEY` 后重跑本节并回填真实回复。

## 五、核验中发现的与文章不一致之处

1. **BOM 不是一个，是两个。** 文章第 02 节写「依赖交 BOM 统一管理」，实测
   `spring-ai-alibaba-bom:1.1.2.2` 只管理 `agent-framework`、`graph-core`、`studio`、`sandbox`、
   `starter-a2a-nacos` 等；`spring-ai-alibaba-starter-dashscope` 由
   `spring-ai-alibaba-extensions-bom:1.1.2.2` 管理。只引入前者会在构建期报
   `'dependencies.dependency.version' ... is missing`。本仓库两个 BOM 都引入。
2. **无密钥不能启动。** DashScope 自动配置在启动期即断言 api-key 非空，
   因此「无 Key 也能起服务」不成立，测试改用测试专用假 Key。
3. **版本基线可核验。** SAA 1.1.2.2 的 POM 显式声明 Spring AI 1.1.2 与 Spring Boot 3.5.10，
   本仓库按该组合对齐；`spring-ai-alibaba-bom` 另有 1.1.2.3、1.1.2.4-security-fix，
   `2.0.0-M1.1` 为 Pre-release，按文章口径不进生产。
