
门禁规则：

| 规则 | 配置 | 拦住什么 |
|------|------|----------|
| `requireJavaVersion` | `[21,22)` | JDK 8/11/17 混用导致的 `UnsupportedClassVersionError` |
| `requireMavenVersion` | `[3.9,)` | 机器上的旧 Maven 带来的不一致构建 |
| `dependencyConvergence` | 同构件两个版本即失败 | 依赖冲突导致的 `NoSuchMethodError`、自动配置失效 |

## 五、端到端：用 wrapper 起服务并完成一次真实对话

```console
$ ./mvnw -B -ntp -pl digital-human spring-boot:run     # 带 DEEPSEEK_API_KEY
Tomcat started on port 8080 (http) with context path '/'

$ curl -s --noproxy '*' http://localhost:8080/actuator/health
{"status":"UP"}

$ curl -s --noproxy '*' "http://localhost:8080/api/chat?q=用一句话说明你能做什么"
我能陪你聊天、解疑答惑，还能帮你查资料、出主意、写东西。
__HTTP__200 time=9.055805s
```

配上 enforcer 门禁后，`validate` 阶段先验环境、`test` 阶段再验代码，最后服务能起、能真实对话——
这才是文章说的「全新机器 clone → 配置 Key → 能对话 → 模块级测试通过」的可复现闭环。
