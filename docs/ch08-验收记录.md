### 验收 1：元数据契约（检索日志实证）

```console
c.e.d.service.ProjectKnowledgeRetriever : [retrieve] projectId=1 docName=深圳展厅参观手册.md chunkIndex=0 score=0.2519762663855506
c.e.d.service.ProjectKnowledgeRetriever : [retrieve] projectId=2 docName=客户B专享政策.md chunkIndex=0 score=0.4511071116392083
o.s.ai.vectorstore.SimpleVectorStore    : Calling EmbeddingModel for document id = p1-深圳展厅参观手册.md#0
```

每条命中都带项目归属与 chunk 序号；chunk id 是确定性的（`p{projectId}-{docName}#{index}`），
所以重复入库是覆盖而不是堆积。

### 验收 2：隔离（本掌最重要的一条）

两个项目各灌一份知识：

| 项目 | 文档 | 关键内容 |
|------|------|----------|
| 1 深圳展厅 | 深圳展厅参观手册.md | 开放时间九点到十八点、团体讲解提前三天、电话 0755-12345678、二十个车位 |
| 2 客户B展厅 | 客户B专享政策.md | **内部折扣七折**、服务热线 400-888-6666、上门安装 |

拿**项目 2 的问题**去问**项目 1**（文章里那次「把 B 的报价讲给 A 的客户」的事故场景）：

```console
$ POST /api/projects/1/rag/ask  {"question":"客户B的专享折扣是几折？服务热线是多少？"}
{"answer":"这个项目的知识库里没有和该问题相关的内容，我不能凭猜测回答。…",
 "sources":[],"refused":true}
```

服务端日志显示命中的只有项目 1 的 chunk，且得分被下限滤掉：

```console
[retrieve] projectId=1 docName=深圳展厅参观手册.md chunkIndex=0 score=0.0
```

正向对照（在项目 2 里问同一个问题）：

```console
$ POST /api/projects/2/rag/ask  {"question":"客户B的专享折扣是几折？服务热线是多少？"}
{"answer":"客户B的专享折扣是七折。[1]  \n客户B的服务热线是 400-888-6666。[1]",
 "sources":[{"docName":"客户B专享政策.md","chunkIndex":0,"score":0.4511071116392083,…}],
 "refused":false}
```

同一句话：在错误项目里拒答，在正确项目里带出处答对。这就是隔离生效的完整证据。

## 三、核验发现与踩坑

1. **阈值 0 会让「无依据拒答」永不触发**：`similarityThreshold=0` 时任何问题都能拿到 topK 条
   （哪怕得分是 0），于是「知识库里没有」这条分支永远不会走到。处置：向量库阈值保持 0（宽口径取候选），
   另设业务侧相关度下限 `min-score` 专门判「有没有依据」。这条是写代码时才撞出来的，不是读文章能读到的。
2. **元数据必须在切分之后重建**：切块产生的是新 Document，原始 Document 上的 metadata
   不能想当然地认为被带过去了（文章第 06 节诊断三就是这个现象：有引用但来源是 null）。
3. **回读校验很有价值**：写入后立刻用过滤条件查一次，把「写入没生效」这类延迟暴露型缺陷
   提前到调用时刻。本掌把它做成硬校验（查不到就抛异常）。
4. **PowerShell 传中文 JSON 仍需走文件**：`-d '{...}'` 会被转成 GBK 导致 400，
   必须 `[System.IO.File]::WriteAllText` 写 UTF-8 文件后 `-d @file`（第 3 掌就踩过，这次又确认一次）。

## 四、本掌遗留问题

- **向量化是词法实现，不是语义 embedding**：召回的「同义改写」能力为零，
  所以上面的分数与命中率**不能**当作生产指标；换真实 embedding 只需替换 `RagConfig` 里的 Bean。
- **向量库仍是内存实现**：真源在 MySQL、启动重建，但多实例不共享索引，重启后有一段重建窗口。
- **FAQ 类问答对可能被切开**：按字符数切分会把问题和答案分到两个 chunk（短文档当前没触发，
  但长 FAQ 会），生产建议「一问一答作为一个 Document」。
- **单跳检索**：多跳问题（「折扣和上门安装有关系吗」）无能为力，Two-step / Agentic RAG 应由评测数据驱动引入。
- **没有评测集**：命中率、拒答率、引用正确率都还没有量化基线（第 15 掌的试炼评测）。
