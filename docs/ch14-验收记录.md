## 三、核验发现与踩坑

1. **顺序契约没有任何注释保护**：`InterceptorChain` 只写了「先声明的在外层」（:84），
   没有写「重试必须在这个错误拦截器的更外层」。两个拦截器相隔 4 天进入主仓，组合语义无人声明。
2. **`ToolRetryInterceptor` 的默认退避是「秒级」**：`initialDelay=1000`、`backoffFactor=2.0`、`jitter=true`，
   也就是说 `maxRetries=2` 时最坏会在**调用线程上 sleep 1s + 2s**。在 Web 请求线程里挂它要留意。
3. **`maxRetries` 与 `maxAttempts` 语义不同**（后者含首次调用），main 上已经改名——
   升级依赖时这是会静默改变行为的点。
4. **`Write-Host` 的输出不能进管道**：定位脚本第一版用 `Write-Host`，导致证据文件是空的。
   改成 `Write-Output` 之后既能上屏也能落盘——「可复算」的前提是**输出可被机器消费**。
5. **源码缓存的目录解析陷阱**：`$PSScriptRoot` 在 `param()` 默认值里取不到（PS 5.1），
   路径会退化成相对当前目录，进而写出 `D:\.source-cache`。默认值改到脚本体里算。

## 四、本掌遗留问题

- **Issue 只到草稿**：提交到上游是代表个人账号的动作，本掌把证据准备到可提交，
  是否提交由仓库主人决定（这也是「协作」与「代替别人发声」的边界）。
- **行号断言没有自动化**：目前靠脚本+人工比对，升级依赖时不会自动报警（`ToolRetrySemanticsTest`
  里的行为断言会报警，但行号不会）。
- **只覆盖了一个行为**：本掌的链路是「工具失败重试」，模块地图是围绕它做的，不是全量源码地图。
- **生态仓库未核验**：Extensions 与 Examples 的版本状态没有逐一确认（本掌只锁主仓）。
