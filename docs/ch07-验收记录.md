本章关键断言：

| 用例 | 钉住什么 |
|------|----------|
| `queryAvailability_shouldReturnBusinessErrorCodeInsteadOfThrowing` | 业务错误用 `{status:ERROR, error.code}` 返回，不抛异常 |
| `queryAvailability_shouldRejectMalformedDateAsInvalidArgument` | 参数错误 = `INVALID_ARGUMENT`，与业务错误分开 |
| `remote_shouldExposeDiscoveredRemoteToolsAndAuditThem` | 远程工具同样被审计包装（远程调用更要留痕） |
| `remote_shouldBeEmptyWhenMcpClientIsNotConfigured` | MCP 客户端未启用时远程集为空，不影响本地工具 |
| `discoveryCheck_shouldFailFastWhenRemoteToolListIsEmpty` | 清单为空 → 启动失败，消息里点明常见原因 |
| `discoveryCheck_shouldPassWhenRemoteToolsExist` | 有工具时正常通过 |
| `call_shouldFallBackToExceptionTypeWhenMessageIsNull` | 异常无 message 时审计留异常类型，不写「null」 |

## 四、验收 3：三类故障各有明确表现

| 故障 | 实测表现 |
|------|----------|
| 端点端口不通（8099） | 启动失败：`java.nio.channels.ClosedChannelException`（连接层） |
| 路径/协议不匹配（客户端 `/sse` vs 服务端 `STREAMABLE /mcp`） | 启动失败：`McpTransportException: Sending request failed, 404 Not Found from GET/POST http://localhost:8081/sse` |
| Server 运行中断连 | **启动不失败**；调用失败 → 审计 `ERROR`；模型回答「暂时查不到…稍后再问我一次」 |
| 业务错误（查没有排期的日期） | 调用**成功**，内容 `{"status":"ERROR","error":{"code":"NO_SLOT_AVAILABLE","message":"展厅「深圳展厅」在 2026-12-31 没有排期…"}}`，`isError:false` |

### 恢复能力（实测）

停掉 MCP Server 后提问 → 依赖模型降级回答；**重启 Server 后，同一个数字人进程未重启即恢复**：


## 五、核验发现与踩坑

1. **文章里「404 被静默处理成没有工具」在本栈没有复现**：Spring AI 1.1.2 + mcp-spring-webflux 0.17.0
   会把 404 与 URL 明确抛出来并导致启动失败。我们的 `McpDiscoveryCheck` 守的是另一种情况
   （客户端初始化成功但工具清单为空）。差异已写进设计文档第五节。
2. **异常 message 可能为空**：Server 断开时 MCP 客户端抛出的异常没有 message，
   审计里原本只剩「工具执行失败：null」。已改为回退到异常类名，并补了单测。
3. **门禁第三次拦住东西**：引入 MCP Client 后 `dependencyConvergence` 报
   `swagger-annotations-jakarta` 2.2.38（spring-ai-model）与 2.2.36（mcp-annotations）分叉，
   按既有口径统一到较高版本。
4. **PowerShell 读写 Java 文件会引入 BOM**：用 `Set-Content -Encoding UTF8` 改 `.java` 会被 javac 拒绝
   （`非法字符: '\ufeff'`），且 PS 5.1 默认按 ANSI 读会把中文读坏。改法：Git 回滚后用编辑工具重做，
   或统一用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`。

## 六、本掌遗留问题

- **无认证**：Server 暴露在 HTTP 上，任何能访问 8081 的进程都能调用；
  出内网前必须加一层鉴权（第 22 掌的安全边界）。
- **地址仍是配置项**：`MCP_SERVER_URL` 硬编码在配置里，扩容与灰度做不了（第 13 掌接 Nacos）。
- **无重试与熔断**：Server 抖动时每次请求都直连失败；当前靠模型降级回答，没有客户端侧退避。
- **工具描述没有变更评审机制**：文章强调「描述就是接口契约，改描述要走评审」，
  本仓库目前只能靠 code review。
- **Server 侧没有持久化调用日志**：审计在调用方（数字人）一侧，Server 视角看不到谁调过。
